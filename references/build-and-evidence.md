# Build And Evidence

## Write The Contract

Before editing, record `.taste-loop/intent.md`:

- design intent and selected direction;
- product, audience, primary task, and rationale;
- selected quality references and the principle taken from each;
- behavior and content constraints;
- visual anti-goals;
- required routes, viewports, states, and motion;
- observable acceptance criteria for hierarchy, readability, interaction, and responsiveness.

This contract constrains later criticism.

## Implement The System

- Preserve behavior and project conventions unless change is approved.
- Apply the direction across the visible system, not only the most photogenic screen.
- Cover loading, empty, error, long-content, focus, hover, and reduced-motion states when applicable.
- Reuse supporting tokens and components. Change the system when local overrides would drift.
- Get approval before paid generation. Record generated asset sources and usage constraints.

## Capture Comparable Evidence

Map every claim to evidence. Keep routes, content, viewports, and capture conditions stable.

- Capture enough composition to judge hierarchy and flow.
- Add close views only for details that the full composition cannot show.
- Include the previous candidate beside the new candidate for correction rounds.
- Recapture invalid comparisons.
- Treat static frames and direct observation as diagnostic only. Verify motion with continuous evidence from before the trigger through the settled state, including meaningful intermediate frames.

Keep useful current and comparison evidence only. Remove obsolete or sensitive artifacts.

## Verification Boundary

Per round, smoke-test changed flows and capture focused deltas. Do not run the full suite or claim full verification.

Before acceptance, run the complete applicable matrix:

- primary flows and important routes;
- mobile, intermediate, and desktop viewports with realistic, short, long, and missing content;
- loading, empty, error, overflow, asset-failure, and runtime-error states;
- keyboard, focus, semantics, contrast, text scaling, and reduced motion;
- continuous animation, frame-level glitches, performance targets, and asset cost;
- project lint, type, test, and build commands.

Check the rendered product, not only source. Record tools, evidence, failures, and limits.

## Subtract Before Exit

Remove decoration, copy, controls, containers, and motion that do not support hierarchy or tasks. Recheck the contract so subtraction does not erase required cues.
